# 開発の進め方 (dev-process)

人間・AIどちらが作業しても同じ流れになるよう、開発プロセスをここに固定する。

## フロー

1. **計画**: 着手前に `docs/plans/YYYY-MM-DD-<topic>.md` を書く
   - 背景 (なぜやるか) / 変更内容 (何をどのファイルで) / 検証方法 を必ず書く
   - 1行修正などの軽微な変更は省略してよい。機能追加・複数ファイルにまたがる変更は必須
2. **ブランチ**: `main` から作業ブランチを切る
   - 命名: `feat/<topic>` / `fix/<topic>` / `docs/<topic>`
   - コミットは「prefix: メッセージ」形式 (例: `feat: クリック波紋を追加`)
   - **コミット・マージはユーザーの承認を得てから行う** (~/.claude/CLAUDE.md のルール)
3. **実装**: 計画mdに沿って実装する。計画から外れたらmdを更新する
4. **検証**: `swift build` + 起動スモークテスト + 変更箇所の手動確認。結果を計画mdの「結果」節に追記
5. **ドキュメント反映**: 仕様が変わったら docs/ (requirements / design / features) と README を更新
6. **リリース**: `make dmg` → GitHub Releases にアップロード (→ README「リリース手順」)

## ディレクトリ

```
docs/
  plans/          … 実装計画 (このプロセスの成果物。時系列に溜まる)
  design/         … 恒常的な設計ドキュメント
  features/       … 機能別仕様
  requirements.md / tasks.md / open-questions.md
```

## 注意

- docs に「ユーザーの希望」を書くときは、本人の発言を確認してから書く (過去に誤記録の事故あり → open-questions #1)
- クラッシュ報告を受けたら: クラッシュレポートのスタックから原因を特定 → 計画md (または fix ブランチ) で修正 → 同種の問題がないか横展開で確認
