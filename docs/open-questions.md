# 未確定事項・考慮事項 (open-questions)

決まったらこのファイルを更新し、関連docsに反映する。

## 1. 【解決済み】Flutter で作るか、Swift ネイティブで作るか → **Swift (SwiftUI) に全面移行済み**

- 当初この項には「ユーザー希望は Flutter」と記録されていたが、**これは誤りだった (ユーザーはそのような希望を出していない)**
- Flutter + Swift ハイブリッドで一度実装したところ、懸念どおりコア機能 (録画・波紋・範囲選択・スクショ) はすべて Swift 側になり、Flutter は3画面のUIとChannel橋渡しコストだけが残った
- 2026-07-08、SwiftUI に全面書き換え。アプリサイズ 約50MB→約3MB、起動高速化、ビルドは SwiftPM + Makefile のみ (Flutter SDK 不要)

## 2. 【クローズ】Tailwind CSS の利用 (Flutter前提の論点だった)

- SwiftUI 移行により論点自体が消滅。デザイントークン (ダーク + ティール) は `UI/Theme.swift` の `Brand` に定義

## 3. コーデック: H.264 か H.265 (HEVC) か

- HEVC は同画質で ~40% 軽い。macOSはハードウェアエンコード対応
- ただし GitHub上のブラウザ再生 (特にWindowsのChrome/Firefoxの閲覧者) で再生できないリスク
- **現方針: デフォルト H.264**。設定でHEVCを選べるようにするのは後回し (M6以降)
- TODO: 実際にHEVC mp4をGitHub PRに貼って、他環境で再生確認してみる

## 4. App Sandbox / 配布

- 個人利用・自分でビルドするだけなので **Sandbox無効・notarizationなし** で進める
- `make install` でビルドした .app を /Applications に置いて使う。`make dmg` で配布用dmgも作れる (ad-hoc署名)
- 将来配りたくなったら: Developer ID署名 + notarization が必要 (年99ドル)。今は考えない

## 5. 範囲選択のディスプレイまたぎ

- ディスプレイをまたぐ矩形選択は、解像度・スケール係数が異なると画像合成が複雑
- **現方針: 選択は単一ディスプレイ内に限定** (Awesome Screenshotもブラウザ1窓なので同等以上)
- 需要が出たら再検討

## 6. 録画中の波紋を「常時ON」にするか

- 現方針: 録画中のみ。プレゼン用途 (録画せず波紋だけ欲しい) が出たら設定追加

## 11. 【解決済み】音声2トラックのミックス

- 2トラックのままだと再生側で片方 (システム音声) しか再生されない問題が実機で発生 (2026-08-25)
- **停止時に `AVAssetReaderAudioMixOutput` で1本のステレオAACへミックスする後処理を実装** (`AudioMixdown.swift`)。
  ビデオは再エンコードなしのコピーなので画質・サイズ・処理時間への影響なし
- ミックス失敗時は2トラックの元ファイルをそのまま出力する (録画を失わない)
